# Flap-pick 공통 변경과 SAC에 남은 문제

대상 실행: `sac_20260909_023417_7a1563`, 1500 iteration 완료.
현재 rewards.py, flap_grasp.py, reward 설정, observations.py와 초기 task 설정은
이 실행의 소스 스냅샷과 동일하다. 이 문서는 분석 기록이며 추가 변경·재학습은 하지 않았다.

## 관측된 문제

- 유효 transition 93,720,785개, 완료 episode 225,150개에서 성공 0회.
  `grasp_right`는 iteration 1029의 한 환경·한 step에서만 참이었다.
  모든 유효 step에서 hard `ready_to_close`는 0, hold는 0이었다.
- 최상의 연속 50 iteration(142–191)에서 목표 거리 19.16cm, 정렬도 0.933.
  마지막 50회에서는 거리 41.58cm, 정렬도 0.548로 악화됐다.
  값은 모든 유효 transition으로 가중한 평균이며 이전 실행의 마지막-step
  평균과 동일한 지표가 아니다.
- 마지막 50회 충돌 실패율은 episode 수로 가중해 10.04%다.
  항목별 평균 보상은 접근 -0.03465, 접촉 -0.01667, 닫기 -0.01120,
  실패 -0.01503, prelift 흔들림 -0.00984다. Lift/hold 기여는 0이다.

## 공통 보상에 남은 설계 문제

이번 연속 닫기 보상은 준비도 p가 1보다 작으면 목표 간격에 `(1-p)×40mm`를
더한다. 거리 20mm, 정렬도 0.96, straddle 오차 0이면 p≈0.644이고,
목표 간격은 flap 두께보다 **14.24mm 넓다**. 이 상태는 기존 hard 준비 조건
(거리 <25mm, 정렬도 >0.95, flap 목표가 두 pad 사이)을 만족한다.
따라서 준비 조건을 만족해도 비용이 실제 접촉보다 열린 간격을 선호할 수 있다.
이는 수식상 확인되는 목표 불일치이며 실제 실패의 기여율은 측정하지 않았다.

또한 거리·정렬·straddle의 지수 항을 곱하는 준비도는 먼 거리에서 매우 작다.
Hard gate를 연속식으로 바꿨어도 접근 초기에 닫기 관련 보상 차이가 작을 수 있다.
접근 비용 자체는 올바른 방향의 연속 신호다. '전체 보상이 상수' 또는 '정지가
최적이어서 그렇게 학습했다'고 결론 내릴 수는 없다.

접촉 비용은 실제 접촉 전 거의 일정하고 lift/hold는 실제 파지 이후에만 생긴다.
큰 버퍼가 있어도 성공적인 접촉·상승 경험이 거의 없었다. 제어 가능한 안전한
접근·닫기 경로는 아직 독립적으로 입증되지 않았다. 이전 진단 IK의 실패는
도달 불가능이나 좌표 오류의 증거로 사용할 수 없다.

## PPO·SAC·DPPO가 같은 flap-pick 환경을 쓸 때 공유하는 변경

| 구분 | 변경 | 시점 |
|---|---|---|
| EEF | wrist 고정 offset 대신 실제 두 손가락 충돌면 중심의 중점 사용 | 앞선 EEF v2 |
| 관측 | 양손 jaw gap·hard ready-to-close 추가, 해당 구성 223→227차원 | 앞선 EEF v2 |
| 호환성 | flap_control_version=2와 pad geometry를 계약에 기록 | 앞선 EEF v2 |
| Shaping | 접근·정렬·접촉 및 안정 파지를 비양수 비용으로 표현, 실제 lift/hold는 보상 | 앞선 보상 변경 |
| 닫기 | hard 준비 gate 기반 상수 비용에서 연속 준비도·목표 간격·조기 닫기 비용으로 변경 | 이번 변경 |
| 기하 정보 | flap 두께와 두 pad 사이 구간 밖으로 벗어난 거리 계산 추가 | 이번 변경 |
| 마찰 | s200062_integrated 설정의 정적/동적 마찰 20/16 재사용 | 이전 배포 반영 |

이 공유 범위는 `FlapPickRewardsCfg`와 같은 task 구성을 선택한 실행이다.
모든 task/외부 LeRobot policy에 자동 적용되는 것은 아니다. 새 관측 계약에
맞지 않는 기존 checkpoint/dataset은 그대로 호환되지 않는다. 이미 실행 중인
PPO가 이후 수정한 Python 보상을 자동으로 사용했다는 의미도 아니다.
비교할 때 각 실행이 시작할 때의 소스와 manifest/env 설정을 확인해야 한다.

## 유지한 공통 조건

- 오른손으로 flap 한 장을 집어 들고, 반대손으로 받칠 수 있다.
- Robot–rack/주변 장애물 접촉은 0.1N 초과 시 실패한다. Box–rack 안착 지지는
  별도로 취급한다. 충돌 판정은 settling 중에도 유지한다.
- 파지 전 박스의 수평 이동·회전·속도에 비용을 주고, 실제 파지 후 상승을 허용한다.
- Settling 후 기준 자세를 확정하고 action을 허용하는 환경 동작은 유지한다.
- Reset 자세·분포는 유지하며 curriculum은 추가하지 않았다.

## SAC 전용 변경과 남은 불확실성

이번 replay 필터, 유효 데이터만 쓰는 관측 정규화, warmup 기준,
부분적으로 ready인 step의 update 비율 조절은 SAC runner에만 적용했다.
4096 env, replay 2200만, 유효 warmup 200만, batch 1024/updates 4도 SAC 실행 설정이다.
PPO/DPPO rollout 데이터 필터까지 변경한 것이 아니다.

모든 유효 step의 항목별 보상·접촉 지표 집계도 이번에는 SAC에서 활성화했다.
Pre-reset task metric 보존 기능은 SAC/DPPO가 공유하는 환경 mixin에 있지만
SAC runner가 이 기능을 켠다. 기존 terminal observation bootstrap 동작은 유지했다.

Warmup과 replay window 문제를 고친 후에도 접근·정렬이 후반에 악화됐다.
SAC alpha/Q/optimizer 설정은 바꾸지 않았고 온라인 정규화도 정상 제어 중 계속
갱신된다. 탐색 경험 부족, 보상 목표 불일치, Q/actor 학습 불안정의 영향을
이번 실행 하나로 구분할 수 없다. 이번 모델의 Q 대 실제 rollout return 비교는
추가 수행하지 않았으므로 이전 모델의 Q 과대평가 수치를 그대로 적용하지 않는다.

다음 수정의 우선순위는 준비 조건과 물리 접촉 목표 간격을 일치시키는 것,
실제 관절/EEF 제어 경로를 짧게 확인하는 것, 이후 동일 보상에서 SAC의
정규화·entropy/value 설정을 따로 비교하는 것이다. Curriculum 추가는 별개 결정이다.
