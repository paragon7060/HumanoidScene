# 장기 SAC의 저장공간과 평가 모델 보존

현재 SAC9개는 그대로 진행한다. GPU3의 새 수정 장기도 TRAIN6,144이며,
원래 base·box·flap 무작위화와 양손 파지·유지·들기·안전 기준을 유지한다.
학습 성능은 [진행 기록](RL_V2_SAC_PROGRESS_20261009.md)에서 확인한다.

## 실제 수행한 로컬 이동

RAM 저장소의 불변 DEV 모델38개, 3,718,858,260bytes(약3.46GiB)를
로컬 디스크로 옮겼다. 원래 경로에서 파일을 계속 읽을 수 있도록 디렉터리와
별칭을 원자적으로 교환했고, 모델 bits·SHA256·읽기 전용 regular-file 상태를
다시 확인했다. 활성 학습 checkpoint·replay·HDF·로그는 변경하지 않았다.
이는 Drive 백업이나 모델 삭제가 아니라 같은 서버 안의 저장 위치 이동이다.

[relocate_protected_dev_models.py](../scripts/rl/relocate_protected_dev_models.py)는
명시한 실행·DEV·소스와 일치하는 보존 증명만 읽는다. 모델 하나만 든 불변
폴더, 최소120초의 저장 완료 시간, SHA256·소유자·원래 경로를 검사한다.
기존 경로를 읽는 독자가 있어도 경로가 사라지지 않게 Linux `RENAME_EXCHANGE`를
쓴다. 이 기능이 없으면 복사 검증 단계에서 원본을 유지하며 실패한다.

실제 CPU worker1,960,125는 빈 CUDA mask로300초마다 같은 여섯 장기 실행의
명시한101개 증명을 확인한다. 새 모델을 복사하기 전 디스크 여유20GiB 미만이면
이동을 기다린다. 원래 평가/학습 모델을 바꾸거나 GPU를 재시작하지 않는다.
원자적 교환 중 연속 읽기·체크섬 충돌·변경된 소스·추가 파일·멱등성 등을
검사한7개 테스트가 통과했다.

## 장기 용량 추정의 한계

08:05 KST의 파일 크기 기준으로 일반 디스크 여유88.17GiB, RAM 저장소
여유131.22GiB였다. HDF·replay·metrics·현재 checkpoint·모든 예정 DEV
모델을 포함했다. 이후 모델 이동이 계속된다면 추정 잔여 여유는 각각
약8.90GiB·7.64GiB다. 이동이 지금 멈춘다면 RAM 쪽은 약4.16GiB 부족할 수 있다.

이 수치는 완료 wave의 기록량에 근거한 전망이다. 복사 전20GiB 제한 때문에
미래 모델이 모두 이동한다고 보장하지 않으며, 다른 작업의 쓰기·추가 분석
복사본·영상 증가도 제외했다. 여유는 계속 실측해야 한다. 미백업 raw 데이터나
현재 입력을 공간 확보를 위해 삭제하지 않는다.

## 종료 raw 파일의 추가 백업은 시작하지 않음

종료·최종 checkpoint/log Drive 검증을 마친 실행2개의 raw HDF·replay4개,
약29.8GiB는 로컬에 보존한다. 자동 승인 검토가 기존 checkpoint/log 승인과
별도로 이 raw 데이터의 외부 전송·검증 후 삭제에 대한 구체적 승인을 요구했다.
추가 업로드 worker는 시작하지 않았고 이 작업의 확보 공간도0이다.

[offload_closed_sac_payloads.py](../scripts/rl/offload_closed_sac_payloads.py)는
검토 가능한 코드만 준비했다. 실행하려면 정리할 종료 폴더와 기존 Drive
`HumanoidScene-RL/<original-run-directory>` 목적지에 대한 승인이 있어야 한다.
원래 관리자의 백업 범위·종료 상태는 바꾸지 않는다. 인증을 새로 만들지 않고,
크기·MD5를 두 번 검증하며 실행 입력·열린 FD·파일 변경을 재확인한 후에만
해당 로컬 raw 파일을 정리하도록 설계했다. checkpoint·로그·영상은 보존한다.
추가 raw 백업, 검증 실패 보존, 활성 FD·입력 보호, 변경 파일 보존, 경로 충돌
거부 등7개 테스트도 통과했다. 로컬 모델 이동 검사와 합계14개다.

raw 파일을 정리한 실행을 재개하거나 원본 전이를 분석하려면 해당 raw 파일을
기존 연결에서 복원해야 한다. 코드·설정의 존재를 업로드 실행/완료로 해석하지 않는다.
