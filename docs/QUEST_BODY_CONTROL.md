# Quest 베이스·허리 속도와 부드러운 이동

2026-09-09 변경. 박스를 잡은 상태에서 급격한 베이스 이동·회전·허리 승강을 줄이기 위한
공통 기본값이다. **이번 변경은 시뮬레이션 및 테스트를 실행하지 않았다.** 파지 유지 여부는
사용자가 직접 확인해야 하며, 박스를 놓치지 않는다는 보장은 아니다.

## 적용 범위와 실행

기존 실행 명령으로 Python 수집기 또는 미리보기를 재시작하면 적용된다.
새 CLI 옵션은 필요 없다. 실제 OpenXR 수집기는 Python 재시작만 하면 된다.
2026-09-15 추가한 오른쪽 그립 modifier를 **브라우저 미리보기**에서 쓰려면 squeeze 전송 코드도 갱신한다:

```bash
./setup_quest_browser.sh --patch-only
npm --prefix .external/cloudxr-js-samples/simple run build
```

이후 미리보기 Python을 재시작하고 Quest 페이지를 새로 고친다. 이번 작업에서는 이 명령을 실행하지 않았다.

- `quest_collector.sh collect` / `collect_quest_teleop.sh`: 컨트롤러 `scaled`, `absolute`, `relative` 공통.
- `preview_quest_browser.sh`: 같은 `TeleopBodyMapper`를 사용하여 동일 적용.
- 팔의 `--arm-response` / `--arm-ik` 선택과 무관하다. 팔·머리의 추종 속도는 이번 변경에서 건드리지 않는다.
- 맨손·자유 시점·모드 전환 대기 중 베이스와 허리를 고정하는 기존 동작은 유지한다.
- S56은 베이스 평면 이동·회전만 적용하며, 없는 허리 승강 축은 새로 만들지 않는다.
- 정책 평가/RL 등 Quest mapper를 거치지 않는 별도 제어기의 궤적을 바꾸는 설정은 아니다.

## 공통 제한

| 조작 | 최고 속도 | 가속·감속 한계 |
| --- | --- | --- |
| 왼쪽 스틱: 전후·좌우 | **0.15 m/s** (15 cm/s) | **0.25 m/s²**, XY 벡터 크기 기준 |
| 오른쪽 스틱 좌우: 베이스 회전 | **0.45 rad/s** (약 26°/s) | **0.75 rad/s²** |
| 오른쪽 스틱 상하: 허리/몸통 높이 | **0.10 m/s** (10 cm/s) | **0.20 m/s²** |
| 오른쪽 아래 그립 + 스틱 상하: 몸통 전후 | **0.10 m/s** | **0.20 m/s²**, 초기 기준 ±15 cm 이내 |
| 오른쪽 아래 그립 + 스틱 좌우: 허리 yaw | **0.30 rad/s** (약 17°/s) | **0.60 rad/s²**, ±1.20 rad와 URDF 관절 범위의 교집합 |

오른쪽 아래 트리거는 중지로 누르는 **squeeze/grip**이며 검지 트리거는 그리퍼 개폐를 유지한다.
그립을 누른 동안 스틱 **위=몸통 앞으로 / 아래=뒤로**, **왼쪽=허리 왼쪽 회전 / 오른쪽=오른쪽 회전**이다.
이때 오른쪽 스틱으로 베이스 회전이나 높이 승강을 하지 않는다. 왼쪽 스틱은 베이스 이동을 유지한다.
그립을 놓으면 오른쪽 스틱은 기존 베이스 회전·높이 승강으로 돌아가고, 몸통 전후 위치와 허리 각도는 유지한다.
두 조작 사이 전환 시 이전 축의 목표 속도를 즉시 0으로 만들어 잔여 이동을 막는다.

몸통 전후는 knee/leg IK로 현재 목표 높이를 유지하고 waist pitch로 몸통을 세우는 이동이다.
URDF 관절 범위와 도달 가능한 위치에서만 반영하며, 특히 초기 높이에서 한 방향이 제한될 수 있다.
움직이지 않으면 조금 승강한 뒤 전후 입력을 시도한다. S56의 없는 승강/허리 축에는 적용하지 않는다.

오른쪽 그립을 스틱과 함께 한 번 사용하면 **그립을 놓을 때까지 성공 종료·맨손 전환의 길게 누르기를 억제**한다.
기존 길게 누르기를 실행하려면 그립을 완전히 놓고, 스틱을 중앙에 둔 채 다시 길게 누른다.
그립만 먼저 길게 누르면 기존 단축키가 실행될 수 있으므로, 몸통 조작 시에는 스틱과 함께 사용한다.

몸통 action은 기존 6채널에서 **7채널**로 늘어나 마지막에 `waist_yaw_joint` 위치 목표가 추가된다.
기존 채널 순서는 유지한다. 표준 양손 그리퍼 구성에서 relative는 23D, scaled/absolute는 25D다.
LeRobot/HDF5의 `action_layout`도 갱신되므로 **이전 schema의 데이터셋에 이어 쓰지 말고 새 경로를 사용한다**.
2026-09-15 변경도 시뮬레이션·테스트를 실행하지 않았다.

허리 승강은 knee·leg·waist pitch를 함께 조절하며, 높이 범위는 기존 0~+40 cm를 유지한다.
대각선 입력에서도 평면 이동 최고 속도는 0.15 m/s다. 회전과 승강에도 가속도 제한이 있어
출발·스틱 놓기·반대 방향 전환 시 속도가 점진적으로 바뀐다.

**스틱을 놓는 것과 안전 정지는 다르다.** 정상적인 스틱 해제는 감속하므로 약간 더 이동한다.
최고 속도에서 스틱을 놓으면 설정상 베이스는 약 0.6초, 허리 승강은 약 0.5초 후 멈춘다.
제어 tick의 이산화를 제외한 감속 이동량은 평면 약 4.5 cm, 승강 약 2.5 cm다.
A 정지·추적 손실·잘못된 controller packet·자유 시점·모드 전환에서는 속도 필터를 즉시
0으로 초기화하고 허리 목표를 유지한다. 높이/관절 한계에서도 부드러운 감속보다 범위 준수가 우선이다.
이는 목표 명령에 대한 설명이며 실제 물리 관성까지 즉시 정지시킨다는 뜻은 아니다.

## 값을 다시 조절하려면

`src/kuavo_isaaclab_scene/teleop/teleop_body.py` 상단의 다음 공통 상수를 바꾸고 Python을 재시작한다.

```python
BASE_LINEAR_SPEED_M_S = 0.15
BASE_LINEAR_ACCEL_M_S2 = 0.25
BASE_YAW_SPEED_RAD_S = 0.45
BASE_YAW_ACCEL_RAD_S2 = 0.75
TORSO_HEIGHT_SPEED_M_S = 0.10
TORSO_HEIGHT_ACCEL_M_S2 = 0.20
TORSO_FORWARD_SPEED_M_S = 0.10
TORSO_FORWARD_ACCEL_M_S2 = 0.20
TORSO_FORWARD_LIMIT_M = 0.15
WAIST_YAW_SPEED_RAD_S = 0.30
WAIST_YAW_ACCEL_RAD_S2 = 0.60
WAIST_YAW_LIMIT_RAD = 1.20
```

가속도를 낮추면 출발과 방향 전환은 완만해지지만 스틱 해제 후 정지까지 더 오래 걸린다.
속도 필터는 상수 시간의 벡터/스칼라 계산이며 별도의 충돌 검사나 경로 최적화를 추가하지 않는다.
