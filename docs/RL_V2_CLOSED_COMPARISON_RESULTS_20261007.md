# 10/07 완료된 SAC 개발 평가 비교

현재 최고 개발 성능은 성공 명령 유지 비교의 **33/128**이다. 마지막 평가는
21/128로 내려갔으므로 최고 모델을 보존했다. 아래 후속 비교도 아직 안정적인
네 구역 성공이나 다른 박스 크기의 일반화를 입증하지 못했다.

각 평가는 원래 네 구역32개씩 총128개 요청이다. 초기화 실패도 분모에 넣고,
실제 양손 pad 접촉·0.25초 유지·8mm 들기와 안전 조건을 확인했다. 같은 요청
배치라도 물리 reset과 flap 추첨이 동일하다고 가정하지 않는다. 각 실행의
자기 초기 평가와 비교하며, 서로 다른 방법의 차이를 인과 효과로 단정하지 않는다.

| 비교 | 자기 초기부터 전체 성공 흐름 /128 | 최신 중간 좌·우 / 상단 좌·우 | 공통 유효 조건의 초기→최신 |
| --- | --- | --- | --- |
| 성공 제어 명령 유지 | 23→25→23→33→21 | 9·8 / 4·0 | 23→18 /116 |
| 실패 종료 표본25% | 23→14→8→12→14 | 5·8 / 1·0 | 23→12 /116 |
| 기존 정책 추가 장기 학습 | 15→18→19→15→14→13 | 2·7 / 0·4 | 15→13 /116 |
| 성공 보상+64, 기존 낙하 기준 | 15→7→7→2→4 | 4·0 / 0·0 | 15→3 /116 |
| 성공 보상+64, reset 상대 낙하10cm | 13→12→11→10→4 | 3·1 / 0·0 | 13→4 /116 |
| 위 설정에서 실제 정책 동작80% 수집 | 13→1→6→13→0 | 0·0 / 0·0 | 13→0 /116 |
| 남은 시간 관측 추가 | 11→1→2→6 | 1·4 / 0·1 | 11→5 /116 |
| 최고33건에서 시작한 실제 종료 누적 보상 | 27→8→10 | 7·3 / 0·0 | 27→8 /117 |
| 같은 최고 정책의 실제 동작80% 수집 | 27→21 | 9·12 / 0·0 | 27→19 /116 |

장기 학습은 예정된 추가 학습을 계속한다. 성공 보상 확대나 종료 표본 증가가
이번 전체 평가에서 충분한 해결책은 아니었다. 상단의 안전한 접근과 실제 파지,
중간 선반의 성공 유지가 함께 필요하다. 이전+64 정책의 동작80% 수집은 최종
평가0/128로 정상 종료했고 최종 Drive 검증을 확인했다. 랙 충돌81·낙하21건이며
공통 유효116조건의 성공도13→0건이다. 남은 시간 입력 비교는 세 번째 평가에서
6건으로 일부 회복했지만 초기11건보다 낮고 랙 충돌74·박스 낙하27건이었다.
최고 정책에서 시작한 실제 누적 보상 비교도
27→8→10건으로 일부 회복했지만 초기27건보다 낮다. 최근 평가의 랙 충돌은89건이고
상단 두 구역의 성공은0건이다. 장기 학습은 상단 오른쪽4건을 확인했지만 전체13건은
자기 초기15건보다 낮다. 낙하 수정+64 비교는4건으로 끝났고 writer의 정상 종료와
최종 Drive 검증을 확인했다. 최고 모델의 수집 방식만 바꾼 별도 비교는 초기 평가가
27→21/128이며 상단 양쪽은0건이다. 공통 유효116조건에서도27→19건으로 줄었다.
[Actor 학습률만 낮추는 추가 비교](RL_V2_CONSERVATIVE_ACTOR_20261007.md)도 GPU3에서
실행 중이다. 초기27/128은 학습 전 기준이며 첫 학습 후 전체 평가로 개선을 판단한다.

디스크가 가득 찼을 때 모델 보존 관찰자 두 개가 상태 파일을 쓰다가 종료됐다.
학습 writer 오류와 구분해 확인했다. 종료된 평가와 동일한 원래 체크포인트 네
개를 실행·계약·업데이트 수·SHA256·기존 실제 평가 기록에 맞춰 보호했고,
남은 시간 비교의 관찰자만 RAM 상태 파일의 원자적 쓰기로 복구했다.
기존 학습은 재시작하지 않았다. 업데이트 수가 같은 다른 실행의 모델은 섞지 않았다.
복구한 관찰자는 이후 남은 시간 비교의 첫 학습 평가와 같은 actor695/Q4828
모델을 실제로 보호하고 정상 종료했다. 이후 첫 전체128개 평가에서 성공1건,
랙 충돌77·박스 낙하20건을 확인했다. 공통 유효116조건의 성공은11→0건이다.
